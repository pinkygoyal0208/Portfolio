Case study

How I tune a slow report

A pattern I see often, shown with generic table names.

Before · correlated subqueries
SELECT p.ProjectId,
  (SELECT COUNT(*) FROM Responses r
    WHERE r.ProjectId = p.ProjectId
      AND r.Status = 'Complete') AS Completes,
  (SELECT SUM(Amount) FROM Billing b
    WHERE b.ProjectId = p.ProjectId) AS Rev
FROM Projects p;

One subquery runs for every project row, so the work grows with the data.

After · set-based with a covering index
CREATE INDEX IX_Resp_Proj_Status
  ON Responses(ProjectId, Status);

WITH c AS (SELECT ProjectId, COUNT(*) Completes
  FROM Responses WHERE Status = 'Complete'
  GROUP BY ProjectId),
b AS (SELECT ProjectId, SUM(Amount) Rev
  FROM Billing GROUP BY ProjectId)
SELECT p.ProjectId, c.Completes, b.Rev
FROM Projects p
LEFT JOIN c ON c.ProjectId = p.ProjectId
LEFT JOIN b ON b.ProjectId = p.ProjectId;

Aggregate once, join once, and reconcile totals against the old query before switching.
